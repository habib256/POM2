# POM2 v0.8.3

**The Print Shop prints — in colour — and the disk it ships on now mounts.**

v0.8.2 was a packaging release. v0.8.3 is a correctness one. It started as a
one-line check ("does the ImageWriter II print in colour with Print Shop?") and
ended up finding that POM2 was throwing away every byte that graphics software
sent to a parallel printer card, while telling the guest the print had
succeeded. Fixing that made colour printing work for the first time. Making the
test reproducible from the real media made POM2 mount 3.5" flux images.

Around those, a full bug hunt over the modules that had never been swept.

## Highlights

**🖨️ Graphics software can reach the printer at all now.** POM2's synthetic
`PrinterCard` decoded exactly one soft switch, `$C0n1` — the offset its own
`PR#n` COUT trampoline uses. That is the path BASIC, DOS and the Monitor print
through, so every existing test was happy. But a *graphics* program drives the
Apple Parallel Interface directly: it writes the byte to the data latch at
`$C0n0`, pulses the strobe at `$C0n2`, and polls `$C0n4` for ready. All three
were being ignored, `$C0n4` cheerfully answered `0xFF` forever, and the whole
job went into the void while the guest advanced to "PRINTER TEST WAS
SUCCESSFUL". A printer that reports success and prints nothing is the worst of
the available behaviours. The card now takes data on `$C0n0` as well — that is
the real hardware's data latch, so accepting it costs nothing — and `$C0n2`
stays ignored on purpose, because the strobe carries a *copy* of the byte and
taking it too would double every character.

**🎨 Colour, confirmed end to end on the real driver.** With that fixed, *The
New Print Shop*'s own Test Printer was driven from boot to page: Setup reads
`Apple Imagewriter II (C)` / `Apple ][ Parallel` / slot 2, and the job it emits
is **5 194 bytes carrying 13 `ESC K` band selects** — the yellow, magenta and
cyan passes, each followed by a bare CR and its own `ESC G` block so they
overprint on one line. POM2 prints "Welcome to The New Print Shop" in magenta,
green (yellow over cyan) and cyan: three ribbon bands and one subtractive mix on
the page. The same job on the pre-fix card wrote 5 194 bytes and spooled **0**.

Worth stating plainly, since it is the question that started this: the **1984
original** Print Shop cannot print in colour, and the emulator is not why — it
predates the ImageWriter II's colour ribbon by a year, its Setup offers no
`(C)` variant, and its byte stream contains no `ESC K` at all. Colour is a *New
Print Shop* feature.

**💾 3.5" WOZ images mount.** A `.woz` holds bit *cells*; POM2 stores 3.5" media
as a flat block array, so a flux dump had nothing to be mounted *as* —
`Disk35Image` took `.po`/`.2mg` only, and the 5.25" WOZ loader rejected
`INFO.disk_type = 2`. That is what stopped *The New Print Shop 800K.woz*, the
format 3.5" preservation actually ships in, from being usable at all.

It mounts now, and the hard part was already in the tree: the Sony 800K GCR read
path the drive uses to fold guest-written tracks back into an image. It moved to
`src/Sony35Gcr.{h,cpp}` unchanged — same tables, same checksum walk, same MAME
`flopimg.cpp` lineage — and both callers share it, because a second
transcription of that table is a second thing to get quietly wrong. POM2's own
load of the real disk is **byte-identical on all 1 600 blocks** to an
independent offline conversion, and booting straight from the `.woz` prints the
same colour page.

Three things it needed that are worth knowing:

- **A WOZ always mounts write-protected.** Giving blocks back would mean
  re-encoding your flux, which POM2 cannot do; accepting writes and dropping
  them at flush is the failure mode that forecloses.
- **The track is a circle.** Walking it once loses the sector straddling the
  seam — about one per track-side, ~150 blocks on an 800K disk.
- **The file is asked what it is, not measured.** Flux file size is a property
  of the *dump*, so the old "any `.woz` is a Disk II image" rule sent an 800K
  3.5" disk to the wrong drive. `INFO.disk_type` decides now, and the 3.5" bay,
  the Disk Library and the mount dialog all accept `.woz`.

**🐛 Bug hunt 8 — four more defects, in modules that had never been swept.**

- **The ca65 DHGR sprite export read past the end of the buffer it was
  slicing.** It sized its rows from the *un-clipped* shape width, but a DHGR
  line holds 140 colour pixels and the rasteriser drops the rest — so past 20
  bytes of width the export kept counting bytes the picture no longer had, and
  at the UI maxima it read **32 bytes past a 16 KB heap block** (confirmed under
  ASan). The fix removes the disagreement rather than bounds-checking the read,
  and the editor now *says* when a sprite was too wide: a clip you cannot see is
  the reason the arithmetic could disagree for this long.
- **The print head walked off the paper.** `printBitGraph` advanced the carriage
  with no right-margin test, while every other head-motion path in the file has
  one. An over-long bit-image run parked the head **113 inches out on an
  8.5-inch page** and charged 22 emulated seconds of BUSY for dots the raster
  clip had already discarded. Columns past the margin are now dropped — not
  wrapped, which would corrupt the image — and the same job drains in 1.7 s.
  Output-neutral by construction, and pinned as "the narrow page is the wide
  page *cropped*" across 1.4 M dots of screen dump.
- **A ProDOS write-back could merge two files into one and report success.**
  Trailing dots are stripped when composing a host filename, so `README` and
  `README.` both came out as `README` and the second silently replaced the
  first — while both halves reported success and the user was left with one file
  holding the other's bytes. You do not have to go looking for that pair:
  `README` + `README!` in a host folder becomes exactly it. Host names are now
  reserved per directory and a clash takes a numeric suffix.
- **`EchoPlusTMS5220Card` serialized nothing.** Every byte it owns is
  guest-readable, so a rewind restored the machine around a card still holding
  the abandoned timeline's registers. It now snapshots like its siblings.

**🖥️ F10 no longer kills the browser demo.** Toggling full screen in the
WebAssembly build destroyed the running machine and reported it as a load
failure. Full screen goes through `glfwSetWindowMonitor`, which is correct on a
desktop — but Emscripten's GLFW port defines it as `abort(...)`, and an abort
tears the module down. Every published demo has had this, v0.8.2 included. In
the browser, kiosk is now chrome-free with the canvas untouched, which is the
right behaviour anyway: a canvas already fills its page, and real full screen
inside a page belongs to the browser's own control.

**⛶ Full screen has a toolbar button.** It was reachable by F10, the View menu
and the command palette — three routes, none of them visible on screen. It now
sits next to the screenshot and memory-grid buttons and goes through the same
toggle, so the four ways in cannot drift apart.

## Also in this release

- **A `PrinterHistory` timestamp buffer** that could only answer by truncating,
  putting a malformed entry in the durable print index. It was the one warning
  left in the whole first-party build.
- **Two test-suite budgets and one assertion corrected.** A FujiNet test timed
  itself with a stopwatch and asserted a bound that could only ever react to
  host speed; it now asserts the link counters that state the property directly.
- **Swept clean, and worth recording:** the whole suite under ASan+UBSan and
  again under valgrind memcheck (which, unlike ASan, can see reads of
  *uninitialised* memory) — zero diagnostics either way; a ThreadSanitizer pass
  over the emulation controller's real concurrency shape — zero races; 40 000
  mutated snapshots, 12 000 mutated tapes, 6 000 hostile control-server
  requests, 6 000 random machines against the paging and display decoders, 300
  Disk II guests driving 28.4 M nibble flushes, and 1 200 ProDOS trees probing
  for containment breaches — no findings.

## Notes

- No package is signed: macOS is ad-hoc signed (right-click → Open on first
  launch, or clear the quarantine flag), Windows is unsigned (SmartScreen →
  More info → Run anyway).
- Packages carry the ROM set and the UI assets, never a disk library. Bring
  your own images.
- The Pi packages are verified structurally and smoke-launched in CI, on an
  ARM64 runner that executes the same instruction set. CI cannot prove they
  render correctly on real Pi hardware.
