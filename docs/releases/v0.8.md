# POM2 v0.8

**Eight Apple II machines from 1977 to 1988, beam-raced to the scanline.**

v0.7 was the first tagged release and shipped a Linux tarball and `.deb`.
v0.8 is the one you can hand to anyone: a self-contained package for **Linux,
macOS, Windows and Raspberry Pi**, with everything the emulator needs in it —
download, open, boot a disk. It also closes the two largest functional gaps
that were left — the Apple II is on the network, and it prints — and it runs
about **twice as fast** doing it.

## Highlights

**📦 Four platforms, nothing to install.** AppImage (x86_64), a Universal 2
`.dmg` (Apple Silicon *and* Intel), a self-contained Windows `.zip` with no
DLL beside the `.exe`, and an aarch64 AppImage for Raspberry Pi 4/5. Each is
built natively on its own OS in CI, smoke-launched before publication, and
listed in `SHA256SUMS.txt`.

**🪟 The interface got its pass.** Dear ImGui **docking**, so ~33 panels stop
fighting over the screen and you can save a layout; an opaque theme with
**DPI/zoom scaling**; a **command palette** (`Ctrl+Shift+P`); a status bar
that lists every mounted volume; a Disk Library that browses instead of
listing; CRT settings you tune with sliders rather than 13 numbers; and Slot
Config showing which changes are staged before you apply them.

**💽 CP/M, on an Apple II.** A **Microsoft SoftCard** (Z80B clipped onto the
6502 bus, with real DMA arbitration) boots **CP/M 2.2 to `A>`** — the 44K
v2.20 master on a II+ in 40 columns, the 60K v2.23 on a //e in 80 — and the
boot is identical to MAME's, instruction for instruction. The Z80 core
passes **zexdoc and zexall at 100 %**. That opens the CP/M library:
BASIC-80, WordStar, Turbo Pascal, dBase II.

**🎨 A paint editor for all four graphics modes.** HGR, lo-res, **DHGR and
DLGR** pages edited in place on the running machine, with an image importer
that does analysis-by-synthesis in CAM16-UCS perceptual colour (the ii-pix
560-dot model, plus an NTSC 8-px chroma variant), MacPaint fill patterns,
mirror symmetry, onion-skin tracing, a page-1↔2 flipbook, and a companion
**sprite editor** that grabs from the live screen and exports ca65 source.
Pictures save straight into a synthesised ProDOS volume, `BLOAD`-able by
name.

**🌐 The Apple II goes online.** Two Ethernet cards: the **Uthernet I**
(CS8900A, ported from MAME) for IP65 / Contiki, and the **Uthernet II**
(W5100), whose hardware TCP/IP stack POM2 runs straight on host sockets — so
period IRC, telnet and FTP clients reach the real internet with **no extra
dependency and no privileges**, on all three desktop platforms.

**📡 FujiNet relay.** POM2 presents a SmartPort controller and forwards every
call to a real FujiNet — a desktop build over loopback TCP, or **a physical
ESP32 board over USB**. One protocol carries the lot: block storage, the `N:`
network device, clock, printer, modem, CP/M.

**🖨️ Printing, end to end.** The ImageWriter II is complete: real typefaces
(correspondence / draft / NLQ, fixed and proportional) with their
international character sets, four-band colour ribbon with subtractive
overprint, bit-image graphics, a paper tray you can watch fill up, PNG and
multi-page **PDF** export, and a durable print history you can click back
onto the canvas. Two more heads — **ImageWriter I / Apple DMP** — plus an
**Epson FX-80** with its own ESC/P parser. Print from a parallel card, a
Grappler+, the Super Serial Card (so a **//c prints** through its printer
port) or a FujiNet printer unit. There is a **screen dump** command, and the
printer even *sounds* like one.

**⚡ Twice as fast, same output.** A measured optimisation campaign
(`docs/PERFORMANCE.md`): the ROM-banner workload went **0.425 s → 0.212 s**
and a 5.25" boot **0.566 s → 0.255 s**, combining source work (flux-lookup
resume, hot-path bus reads) with a PGO+LTO build recipe. Every step is
verified output-identical by RAM and framebuffer hashes — an optimisation
that moves a hash is a bug, not an optimisation. The display path skips
repainting unchanged text frames (−84 %).

**🍓 Raspberry Pi tier.** POM2 compiles for **OpenGL ES 3.0** from the same
sources (Mesa's V3D caps desktop GL at 3.1 on Pi 4/5, so the default request
cannot succeed there). On top of the generic aarch64 AppImage, CI can build
**core-specific PGO packages** on an ARM64 runner — worth −39 % on a CPU-bound
load and −29 % on a disk-active one, with the Pi compiling nothing.

**🔊 The audio bus goes stereo.** Mockingboard routes AY1 → left / AY2 →
right, the Phasor splits by VIA pair, speech stays centred — MAME's own
routing. The AY synthesis is band-limited (inharmonic energy on a 4 kHz note:
7 % → 0.5 %) and its register replay is re-timed against CPU time, which
fixed the demo-music glitching. A mono fold-down reproduces the old summed
render bit-for-bit.

**💾 Storage that behaves.** The **//c+ boots and writes 5.25"** for real
(three stacked bugs, one repro); SmartPort units get access LEDs and join the
disk turbo; and media write-back is now not just atomic but **durable** — the
data is flushed before the rename publishes it, so a power cut can no longer
leave an empty file where your disk image was.

**🖥️ Kiosk is a mode, not a launch flag.** **F10** moves between exclusive
full-screen and your window at any time, without touching the machine — the
game keeps playing across it.

**🔎 A dozen adversarial bug sweeps.** Subsystem-by-subsystem audits, each
finding verified against the source (and for the worst ones, against a
runnable repro) before being fixed — the largest single pass fixed 21 defects
across ten subsystems. The test suite went from ~130 to **177 tests**, all
green.

## Platform notes

| | |
| --- | --- |
| **Linux x86_64** | glibc **2.27** floor — Mint 19+, Debian 12, Ubuntu 20.04+ |
| **Raspberry Pi** | aarch64, GLES 3.0, Raspberry Pi OS **bookworm** (glibc 2.36) |
| **macOS** | Universal 2, **ad-hoc signed** — first launch needs right-click → *Open*, or `xattr -dr com.apple.quarantine /Applications/POM2.app` |
| **Windows** | x64, **unsigned** — SmartScreen: *More info* → *Run anyway* |

Verify what you downloaded with `sha256sum -c SHA256SUMS.txt`.

Prefer no download at all? The whole emulator also runs in the browser:
<https://habib256.github.io/pom2/wasm/>

## Known limitations

- **Uthernet I on Windows** has no host transport: raw frames need libslirp,
  which POM2 builds against on Linux and macOS only. The Uthernet II is
  unaffected — its stack is in hardware and runs on host sockets everywhere.
- **Uthernet II inbound (`LISTEN`)** is decoded but unimplemented; outbound
  connections are the supported direction.
- **3.5" / SmartPort on //c-class** machines is served by a host-side
  SmartPort block device at built-in slot 5. The //c+ firmware's own
  IWM/UniDisk boot path is deliberately not modelled.
- **In the browser**, settings and window layout do not survive a reload, and
  disks are bundled at build time rather than picked from your machine.
- The **Raspberry Pi package** is built in a pinned bookworm container and
  smoke-launched in CI, which proves it starts and links GLES — not that it
  renders correctly on your particular Pi. Reports welcome.
