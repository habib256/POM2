# POM2 v0.8.2

**Seven packages, one payload list, and a smoke test that actually boots the
machine.**

v0.8 built four packages. v0.8.2 builds **seven** — every platform the tooling
can reach — and, more to the point, it stops trusting them. Each one now has to
prove it carries what it claims and that the binary inside it boots an Apple II
before it can reach a Release page.

It also lands a long-standing rough edge in the emulator itself: the mouse.

## Highlights

**🖱️ The mouse is finally the guest's.** The Apple II Mouse Card is a *relative*
quadrature device, so a host pointer that stops at the edge of the screen widget
starves it: the emulated cursor drifts out of sync and can end up unable to
reach its own clamp edges — an MGTK menu bar it simply cannot walk to. POM2 now
**captures the pointer**: click the screen (or `Ctrl+Alt+G`) and the OS cursor
disappears while motion becomes unbounded, so the guest cursor always gets
where it is going. **`Ctrl+Alt+G` or a middle click gives it back** — the pair
every VM viewer already trained into your fingers — and so does Alt-Tabbing
away or unplugging the card. A `GRAB` badge sits in the status bar for as long
as it lasts, with an on-screen caption saying how to leave.

**📦 Seven packages.** Three new ones join the four from v0.8:

| | |
|---|---|
| `-x86_64.AppImage` | Linux Intel/AMD, glibc 2.27 floor |
| `-aarch64.AppImage` | **new** — ARM desktops and servers, desktop GL |
| `-raspberry-aarch64.AppImage` | Raspberry Pi 3 → 5, GLES 3.0, glibc 2.36 |
| `-pi400-aarch64.AppImage` | **new in the release** — Pi 4 / Pi 400, `-mcpu=cortex-a72` + PGO/LTO (≈ −39 % CPU) |
| `-macOS.dmg` | Universal 2, Apple Silicon *and* Intel |
| `-Windows.zip` | one self-contained `.exe`, no DLL |
| `-web-wasm.zip` | **new** — the browser build, for any static host |

The three aarch64 packages are not redundancy: each targets a floor the others
cannot serve, and the **file name says which to take**. That naming is now
enforced per job — the publish step flattens every artifact into one directory,
so two same-named packages would have overwritten each other in silence.

**📋 One list of what ships.** The package payload — the ROM set, the two UI
fonts, the About photo — was spelled out by hand in four places, and they had
drifted: the browser bundle carried folders the desktop packages never got, and
4 MB of reference photography nothing reads. It is now declared once, in
`packaging/bundle.manifest`, which CMake reads for the install rules *and* the
WebAssembly preload list, and which the macOS and Windows packagers read for
theirs. Adding an asset means editing one file.

**🔍 Packages that have to prove themselves.** Past "does it start", every
release job now runs two checks against the package it just built:

- **payload** — everything the manifest promises is present, and nothing from
  its deny list (the disk libraries, your snapshots, your printouts) leaked in.
  Both failures are otherwise silent: a missing font drops the UI to blank icon
  boxes, a leaked library turns a 6 MB download into a 200 MB one carrying
  media that is not ours to redistribute.
- **boot** — `pom2_headless --frames 300 --screenshot` boots the *bundled* ROM
  through the *packaged* binary, runs 300 frames and fails if the captured
  frame is a single flat colour. `--help` would pass just as happily with an
  empty `roms/`.

**🌐 The online demo cannot go stale in silence.** GitHub Pages serves the
committed `wasm/` folder, so a forgotten rebuild leaves an old demo online with
nothing failing. `tools/wasm_stamp.sh` fingerprints the sources that determine
the bundle and CI refuses a stale one.

## Also in this release

Everything merged since v0.8 was prepared, most of it from a long hardening
pass over the paths where POM2 touches your files:

- **Media write-back is now durable, not just atomic.** Every save already
  committed through a temp file and a rename — atomic for a *reader*, but
  promising nothing about a power cut. Nothing in the tree called `fsync`, so a
  crash could leave a 0-byte file where your only copy of a disk image was.
- **DLGR shadow overruns fixed.** The Paint editor indexed the DLGR page
  through the HGR interleave — out of bounds on both read and write, and one of
  the three sites POKEs the live machine, so a DLGR palette shift scribbled
  across text page 2, user RAM and HGR page 1.
- **Eleven verified defects** from a five-subsystem sweep, plus eighteen more
  across the FujiNet relay and the printer stack, plus bounded handling of
  hostile media and imports, interruptible shutdown, and more robust snapshot
  restore and media ejection.
- **SmartPort dispatch** correctness fixes.
- The browser demo now boots **Total Replay v6.1**.

## Notes

- No package is signed: macOS is ad-hoc signed (right-click → Open on first
  launch, or clear the quarantine flag), Windows is unsigned (SmartScreen →
  More info → Run anyway).
- Packages carry the ROM set and the UI assets, never a disk library. Bring
  your own images.
- The Pi packages are verified structurally and smoke-launched in CI, on an
  ARM64 runner that executes the same instruction set. CI cannot prove they
  render correctly on real Pi hardware.
- Android is not in this release. POM2's GUI is GLFW + desktop OpenGL, so
  Android is a port rather than a packaging job; it will get its own tag.
